In the context of Rockstar Games file formats (specifically *Red Dead Redemption 2* and the RAGE engine), **RPF8** is the archive version format used for game files (following RPF7 used in *GTA V*)[1]. 

When looking into GitHub repositories handling RPF8 and RPF archive encryption types (such as `rpf-archive` libraries, community format docs, or toolkits like OpenIV/CodeWalker derivatives), the structure and encryption parameters typically break down as follows:

### 1. Encryption Types Header Fields
In RAGE RPF archives (including RPF7 and RPF8 formats), internal structure headers specify how individual entries or blocks are encrypted. Across open-source parsers on GitHub, these encryption types are generally grouped into four main constants[2]:
* **`NONE`**: Unencrypted data blocks.
* **`OPEN`**: Designated by the magic string `"OPEN"`. Modded files often ship as `OPEN` so that the game engine can read them without requiring proprietary re-encryption keys[2].
* **`AES`**: Advanced Encryption Standard blocks (less commonly used for main asset files in later RAGE iterations)[3].
* **`NG`**: Rockstar's custom "New Generation" encryption scheme utilized heavily in modern RAGE titles (*GTA V*, *RDR2*)[2][3]. 

### 2. Key Differences in RPF8 (*RDR2*)
While RPF7 (*GTA V*) keys and structures are extensively mapped out in open-source tooling, **RPF8** introduced structural alterations:
* **Hash-based Entries:** Unlike older iterations where file paths or names were stored more explicitly within specific lookup tables, RPF8 entries are heavily indexed and keyed by hashes rather than plain text names. External nametables are typically required to map hashes back to readable asset paths[2].
* **Read vs. Write limitations:** Open-source libraries can readily implement decryption routines for RPF8/NG formats because key constants or patterns can be extracted/scanned from the game executable (`RDR2.exe`)[3]. However, full re-encryption or creation of native-encrypted NG files remains an asymmetrical challenge ("read NG = easy, write NG = the wall") because the specific generation/encryption tables are not natively embedded in standard binaries[2].

### Relevant GitHub Ecosystem Projects
If you are looking for codebases dealing with these specifications, look into:
* **`rpf-archive` / `rage-rpf` (Rust libraries):** Handles reading/writing across RPF0 through RPF8 formats, detailing format magic values and parsing structures[1][4].
* **CodeWalker / gta-toolkit derivatives:** Contain historical implementations of key-Scanning (`GTAKeys.cs`) and RAGE architecture parsing logic that map over into RDR2 research[3].
